## 2. We shipped him a red rectangle across the middle of his video

The marker rectangle `extract_clip_with_in_video_marker` burns into every frame
as aleph2's spatial signal went out in the download. Red-pixel fraction along
the chain: source shot 0.000% → clip sent to aleph2 2.473% → aleph2's return
2.437% → delivered file 2.443%.

`build_aleph_prompt` early-returned on the whole-clip transform branch before
reaching the marker branch — the only branch that says *"Remove the red
rectangle"*. His `replaceWith` was `"Match Shot A exactly: …"` and `"match"` is
in `_TRANSFORM_VERBS`. Reproduced byte-for-byte against the stored
`alephPrompt`.

Fixed in two layers, because a prompt is a request, not a guarantee — job
`qp7pp7nho1r` **did** ask for removal and aleph2 kept the box anyway:

1. The marker branch is now the only branch that may answer when a marker is
   present. All 243 marker-mode combinations carry a removal instruction.
2. `_marker_survived()` walks the rectangle's own perimeter and measures how
   much came back red. Counting red pixels cannot do this job — the reddest
   clip in the corpus is a red coffee mug at 2.1%, above clips with a faint
   box. A mug covers one edge; a box covers four. Over all 42 marker-mode
   clips: survivors 1.000 and 0.997, highest clean 0.045, threshold 0.55 in a
   22× gap.

**2 of 42** marker fixes had shipped a red box. Rebuilt his download offline
through the shipped `restitch()`: 2.506% red → 0.000%, geometry and frame count
unchanged.

Two more defects fell out of tracing it:

- The auto-refund read `error_still_visible`, captured **before** the gates run.
  A clip either gate rejected was correctly kept out of the download while the
  user stayed charged. True for the continuity gate since 15 Sep. Now reads
  `verified_resolved`, so refund means exactly "we did not deliver this".
- `verify.py`'s `len(new_errors) > unfixed > 0` is False when `unfixed == 0`, so
  every fully-fixed job was told *"these are the ones that were not fixed"*.

## 4. Detection was 94% false positives

`scripts/detection-eval/` — the hand-labelled set two previous sessions said was
blocking, and then guessed without. Ten cases: real pairs judged by looking at
the frames, plus clean pairs with a known ffmpeg grade shift so a configuration
cannot score well by going blind. Scored on **false positives first**, because
every finding is offered as a paid repair.

Five of six flagged pairs in a stratified sample were errors that were never
there: the coat; a rifle-scope POV of the same burning vehicle read as an
atmosphere mismatch; doors physically opening onto a garden read as an
inconsistent background; a close-up cut against a wide of one dressing room
read as a lighting mismatch; a bat being placed in a case, mid-action, read as
atmosphere.

**The prompt asked for exactly this.** It said a dramatically different
background in AI footage is *"usually generation inconsistencies, NOT
intentional cuts"*, and that a wrong flag *"costs the user one dismissed row"*.
True when a finding was free to dismiss. False since findings became
purchasable repairs — a wrong one spends real money re-generating footage that
was never broken, returns a degraded video and gets refunded.

| config | false positives | recall |
|---|---|---|
| opus-4-8 + old prompt (was live) | **94%** | 67% |
| opus-5 + old prompt | 94% | **100%** |
| opus-5 + gate only | 17% | 67% |
| opus-5 + exemplars only (8) | 28% | 67% |
| **opus-5 + gate + exemplars (shipped)** | **11%** | 67% |

**Opus 5 is the better vision model, and an earlier claim in this same session
that it was not was wrong.** That claim came from a broken harness: thinking is
on by default on Opus 5 and off on 4.8, thinking counts against `max_tokens`,
and the production budget of 1024 truncated every response into a parse
failure. Configured properly it is the only run that caught all three synthetic
grade shifts. Same price per token as 4.8 — $5/$25 — so it was never a cost
decision.

Applied to `compare_pair` only. The standalone and holistic passes keep
opus-4-8: different prompts, no eval cases yet, and shipping what has not been
measured is how the 94% happened.

## 5. Two corrections from the owner, both of which moved the numbers

**`case10` was not clean.** Judged on the pair alone, a storm clearing to
sunshine reads as a story beat. The other thirteen shots of that film are all
sunny — so the storm is the generator losing the scene at the head of shot 7,
and detection missed it entirely. Reclassifying it put the real false-positive
rate at 94%, not 81%.

This is also why the first version of the intent gate was wrong. It listed *"a
storm clearing to sunshine"* as not-an-error, and that hand-written clause
suppressed a real error. The rule now separates a change **between** two shots,
which is allowed, from one **across the frames of one shot**, which is not.

**A specific user note outranks the gate.** *"His jacket changes colour"* is the
film-maker telling us what is wrong with their own film; they know their intent
and we do not. A generic checklist naming every category is not that, and no
longer reads as one.

## 6. So rules are the floor, and the film-maker is the ceiling

Hand-written rules overfit — the storm clause proves it in one line. Examples
carry the same lesson without legislating the world, and unlike rules they
accumulate.

**`/admin/training`** lists every adjacent shot pair of recent jobs with the
frames detection actually saw, what it reported, and four verdicts: real error,
not an error, we missed one, nothing here. Frames enlarge on click. Every row
expands to the whole film, because judging a pair in isolation is what got the
storm wrong. Verdicts write to `detection_labels` (server-only in
firestore.rules — these labels steer what every user's job gets flagged for),
and `load_exemplars()` feeds the newest 40 into the detection prompt as
calibration that **outranks the written rules**.

This is not fine-tuning and should never be described as one. The verdicts grow
the eval set and ride along in the prompt. Measured: rules alone 17%, exemplars
alone 28%, both 11%.

Admin is `business@alanany.com` by verified Firebase email, `ADMIN_EMAILS` to
add reviewers without a deploy. The email comes off the verified token, never
the request body.

## 7. What this cost, and what that bought

$13.31 of API spend, 2.21M tokens, 250 vision calls over eight eval sweeps.
$2.79 of it on opus-4-8, the rest on opus-5, at identical per-token pricing.
The driver is images — ~8k tokens of frames per call.

The first three sweeps (~$4.60) established the 94%. The remaining five took
the candidate from 33% to 11%. Worth it against a detector that was charging
users for repairs to footage that was never broken — but it should have been
checked before sweep four, not reported after sweep eight.

The eval now caches the frame prefix. They are byte-identical across every run
of a sweep while only the prompt after them changes, so repeat sweeps read them
back at roughly a tenth of the rate.

## Deployed and verified

All three surfaces: `modal deploy`, `vercel deploy --prod`,
`firebase deploy --only firestore:rules`. Pushed to `origin/main`.

Live checks against production, not assumptions:
`/admin/training` 200 · API unauthenticated 403 · wrong secret 403 · queue
returns 36 real pairs, 25 flagged, sorted flagged-first, no missing frames ·
POST → read back → DELETE round-trips · `missed` without a note rejected 400 ·
unknown verdict rejected 400.

A malformed `pairId` used to crash the write with an empty 500 — Firestore
rejects ids matching `__.*__`. Found by probing with exactly such an id. Now a
clean 400, and write failures surface a message instead of failing silently,
because a verdict that looks saved and is not is worse than useless.

## Open

  biases toward silence and is why recall sits at 67% rather than the 100% Opus
  5 reached with the old prompt. Marking **"we missed one"** on real errors is
  what rebalances it. The queue needs both kinds.
- The labels are the owner's judgement calls on a small set. Widen before
  trusting small differences between configurations.
- Standalone and holistic detection passes have no eval cases and are still on
  opus-4-8.
- Still open from 15 Sep: a model can fabricate motion inside a fix that passes
