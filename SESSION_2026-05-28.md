# Scene Fixer — Session Notes (2026-05-28)

## What we shipped today

### 1. Credit model (1 credit = 1 second of Runway output)

Replaced the old "fixes per job run" billing with a per-second model that maps directly to cost.

**Plan limits (new):**

| Plan | Credits/mo | Max upload | Quality |
|------|-----------|------------|---------|
| Free | 5 | 30 sec | 480p + watermark |
| Starter | 20 | 5 min | 720p |
| Pro | 45 | 15 min | 1080p |
| Studio | 120 | 60 min | 1080p |

**How deduction works:**
- At fix time, we query all confirmed, unfixed errors → look up each target shot's duration → sum the seconds → that's the credit cost
- Spend order: monthly quota first, then pack credits (so pack credits are preserved)
- `creditsDeducted` is stamped on each error doc so refunds know the exact amount to return

**Annual subscribers:** credits refresh every calendar month via `monthResetAt < monthStart` — never granted upfront for the full year. Safe.

### 2. One-time credit packs

| Pack | Credits | Label |
|------|---------|-------|
| $10 | 18 | — |
| $25 | 50 | save ~10% |
| $50 | 110 | save ~18% |

Stripe price IDs wired up via env vars (`STRIPE_PRICE_CREDIT_10/25/50/100`). Webhook reads `metadata.quantity` (the actual credit amount) and increments `creditsBalance` atomically.

### 3. Auto-refund on failed verification

When Opus 4.7 verifies a fix and returns `errorStillVisible: true`, credits are automatically returned — no user action required.

- Only fires on the **original** fix (`retryCount == 0`). Retries are free so nothing to refund.
- Refunds exactly `creditsDeducted` seconds back to `creditsBalance`.
- Stamps `autoRefunded: true` on the error doc for auditability.
- Manual refund route still works as a fallback if someone wants a refund after the free retry also fails.

---

### 4. Free tier guardrails

- **30-second upload cap** enforced server-side in Modal's decompose phase (checks ffprobe duration before transcoding). Free users who try to upload longer get a clear error with an upgrade prompt.
- **3 scans/day rate limit** on authenticated free users, enforced in the `/api/jobs/[id]/start` route. Tracks `scanDate` + `scansToday` in Firestore. Error shown directly in the upload UI.

---

### 5. Add-mode verification fix

The Opus verification step was incorrectly flagging "add to shot" fixes as failed — it saw the object present and thought the error was still there.

Fix: detect add-mode (`fixMode == replace` + instruction starts with an add verb) and flip the question. Instead of "is the error still visible?", ask "did the object fail to appear?" This means a successfully added cup correctly resolves as `verifiedResolved: true`.

---

### 6. Audio re-mux in stitched output

Aleph returns silent video. Previously, fixed shots got `anullsrc` (blank silence) under them, cutting any dialogue or music.

Fix: for each fixed shot, extract the original audio at that shot's exact timestamp (`-ss startMs -t duration`) and mux it onto the Aleph output. Safe for lip sync because Aleph only inpaints the red-rectangle region — faces and mouths are pixel-identical to the original.

---

### 7. DiffPlayer vertical video fix

Before/After comparison was broken for portrait-orientation source videos — the "Before" filled vertically while the "After" (Aleph's 1280×720 landscape output) showed with black bars, making them incomparable.

Fix: changed `object-cover` → `object-contain` with `bg-black` on both panes. Both videos now sit in the same 16:9 black box, letterboxed/pillarboxed as needed.

---

### 8. Plan overwrite bug (critical fix)

Clicking any plan on the pricing page was silently downgrading existing users to free.

**Root cause:** `getOrCreateCustomer()` in the checkout route created a new Stripe customer and wrote `plan: "free"` to Firestore whenever no `stripeCustomerId` existed — even if the user already had a plan. Manually-provisioned users (no Stripe customer on record) were especially vulnerable.

**Fix:** Removed `plan: "free"` from `getOrCreateCustomer`. Plan is now only ever written by the webhook after a real payment completes.

Account `business@alanany.com` restored to studio manually via Firebase Admin SDK.

`ADMIN_SECRET` added to Vercel env so `/api/admin/set-fixes` works in production for future manual adjustments.

---

### 9. Stuck "fixing" status recovery

Modal containers get hard-killed on preemption — no exception handlers run, so `fixStatus: "fixing"` on individual error docs never gets cleaned up.

Two-layer fix:
1. **Job level:** `fixingStartedAt` timestamp stamped at fix trigger time. After 20 minutes with no progress, the UI detects the timeout (`fixTimedOut`), suppresses the spinning banner, shows a "Retry" button, and the fix route allows re-triggering a stale job.
2. **Error level:** `useEffect` in the job page watches `job.status`. Whenever the job exits fixing/verifying state, any errors still at `fixStatus: "fixing"` are batch-reset to `"pending"` so the user can interact with them.

---

### 10. Wardrobe / add-to-shot UX

The "Remove" button on wardrobe errors was deleting the jacket entirely instead of restoring the original.

**Wardrobe/hair errors now show:**
- "Restore original" (primary) — pre-fills with Claude's `fixSuggestion`, constrained Aleph prompt that only changes the marked clothing region
- "Replace with…" — manual override
- "Remove" — plain text, below the fold

**Set dressing/prop errors now show:**
- "Add to shot" (primary) — for missing objects; Aleph prompt frames the red box as "where the object should appear"
- "Remove from Shot A instead" — easier/more reliable alternative
- Experimental note under Add

**Aleph prompts updated:**
- Wardrobe: constrains changes to only the clothing/hair inside the red rectangle, preserves face/pose/skin
- Set dressing add: frames the rectangle as a placement target, not a removal region

## Things to watch post-launch

- **Beta/unauthenticated users** are not scan-rate-limited (intentional — beta is a controlled pool)
- **Free tier abuse vector** is now closed: 30s upload cap + 3 scans/day + 5 credits/month
- **Studio economics:** at 120 credits/month, worst-case Runway cost is ~$18 (if all 120s are separate 1s clips, unlikely). Real usage with 5–10s clips puts worst-case at $15–18. $49 revenue → healthy margin at normal usage patterns.
- **Auto-refund doesn't fire on retries** — if someone hits Retry and that also fails, they'll see the manual refund button. This is intentional: the free retry is the goodwill gesture; a second refund would be double-dipping.
