## 3. `verify.py` was withholding videos people had paid for

Found while auditing, and the more expensive of the two bugs.

`verify.py` called `extract_keyframe(...)` and **discarded the return value**,
then uploaded the path unconditionally. `extract_keyframe` returns `None` and
writes *no file* when ffmpeg cannot produce a frame — the exact failure
`ed21956` already fixed in `decompose.py`, whose docstring records that the
unguarded upload "killed the whole job" with `[Errno 2]`.

Confirmed rather than assumed: seeking past the end of a 2.0 s clip returns
`None`, creates no file, and the upload raises `FileNotFoundError`.

It lands later here and costs more. Both call sites (`app.py:414`,
`endpoints.py:117`) run verify **after the user is charged and after `restitch`
has written the output**, unguarded, so the outer handler marks the job
`status: "error"`. The correct fixed video sits in storage while download —
gated on `status == "done"` — refuses to hand it over.

Skipping the shot was already safe: `score_reliable` is
`len(verify_shots) >= input_shots`, so a skip withholds `scoreAfter` rather than
reporting a wrong one.

## 4. The geometry was wrong everywhere, and the code already said so

The pipeline normalised every upload into a **padded 1280×720 landscape frame**.
The padding was not arbitrary — a normalised bbox needs a known frame — but it
made a pillarboxed or portrait upload pay three times, and each cost was
documented in the code before this session:

- **Detection read mostly black.** The keyframe handed to Opus was 1280×720
  carrying **361px of picture (28.2%)**, so ~72% of every image token bought a
  bar, and the source's 540×1080 content was *downscaled* to 361×720 on the way.
- **The fix engines painted into the bars.** From `extract_clip`'s own
  docstring: aleph2 *"treats them as canvas"*, and a corrected clip *"came back
  with the bars filled in with invented houses and lawn."* That applied to every
  portrait upload — "the format most of our uploads arrive in", per `stitch.py`.
- **Output quality.** `post_process` scales the short side by orientation, but a
  padded portrait video *is* landscape at frame level, so it took the landscape
  branch and delivered ~240×480 of picture from a 540×1080 source.

### The invariant now enforced

Bars are measured **once** per job (`contentCrop` on the job doc), nothing is
ever padded, and every stage carries the source's own aspect ratio. So

> keyframe aspect == fix-clip aspect == source aspect

and a normalised bbox is portable with **no transform**. That is what let
`pad_to_frame` be *deleted* rather than defaulted off — the padded frame cannot
come back via a caller passing `True`.

### The design call worth remembering

`fix.py` and `stitch.py` still read the **original upload**, not the normalized
copy, and apply the stored crop at native resolution (`apply_content_crop`).
Reading the normalized copy would have been much simpler and would have rebuilt
a 1920×1080 upload's untouched shots at 720p — a silent downgrade for every pro
and studio render. The crop is applied to the original only, never to a
`prior_clip_url`, or a chained fix would be cropped twice.

### Measured, not assumed

| | |
|---|---|
| landscape | **provable no-op** — every decoded frame byte-identical (framemd5) across all five 16:9 corpus videos; shot counts 18, 14, 2, 2, 1 unchanged |
| pillarboxed keyframe | 1280×720 @ 28% picture → **360×720 @ 100%** |
| free-tier portrait output | 240×480 → **480×960** of picture, **4.0×** the pixels |
| image tokens, 10-shot portrait job | 553k → **156k (72% less)**, and all of it content |
| bbox placement | lands within **0.3%** of target in the burned-in marker, all six videos |

## 5. Three more defects, found while doing it

1. **`grounding.py` normalised Grounding DINO's pixel boxes by a hardcoded
   1280×720.** On an unpadded 360×720 keyframe that put every box at about a
   quarter of its true x. It measures the image now (cached), and *discards* the
   box rather than guessing when it cannot — a wrong bbox is worse than none.
2. **The marker path never honoured `min_dimension`.** Padding satisfied
   seedance2_5's 480px short side by accident; unpadded it is 360. This one was
   a regression **I introduced and caught in the audit**.
3. **`analytics.py`, `detect.py`, `grounding.py` and `fix.py` had no
   `from __future__ import annotations`**, so they raised `TypeError` on import
   under the local 3.9 interpreter. Not cosmetic: you cannot write an offline
   test against a module you cannot import, which is the structural reason this
   code had none. All fourteen modules import cleanly now.

## 7. Final audit of the geometry change

Done before closing. Two fixes (`3e01bf9`), and four things verified with no
change needed:

- **Fixed:** `contentCrop` was written only when bars were found, so a
  re-analysis finding none left the *previous* run's crop on the job and
  fix/stitch would cut into a clean picture. Written unconditionally now.
- **Fixed:** the missing `__future__` guards above.
- **Verified:** `apply_content_crop` preserves duration exactly (62.464 →
  62.464), leaves both streams at `start_time 0.000000`, and the decoded audio
  is **bit-identical** to the source — the one-piece audio copy that A/V sync
  depends on survives.
- **Verified:** it handles a video with no audio stream without falling back.
- **Verified:** `stitch` applies the crop *before* the audio probe and
  `probe_dimensions`, so target geometry comes from the cropped frame.
- **Verified:** `grounding._image_size` returns the true size for a real
  keyframe, caches the repeat, returns `None` when unreachable.
